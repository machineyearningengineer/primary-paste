# Product readiness

Primary Paste should make deliberate selection and paste feel consistent across apps, preserve ordinary macOS behavior, and stay quiet between interactions. Passing a build is necessary; it does not establish compatibility with every editor.

## Onboarding and daily use

Setup explains the interaction in three steps: drag-select text, middle-click an editable field, and continue working. A local practice page gives the user a sentence and paste field without an account, network request, or external dependency. Trackpad users are directed to the optional keyboard shortcut or their gesture mapping tool.

Permissions have a specific purpose and a specific action. Accessibility supports selection reads and editable-field targeting; Input Monitoring supports enabled global gestures; Finder Automation appears only when file capture is enabled. Setup displays actual service state and offers Retry if an enabled service did not start. Optional clipboard modes are choices, not failed onboarding checks.

New installations do not show Setup on every launch. “Continue in Menu Bar” closes Setup and turns off that option for existing installations too. Saved choices remain respected until the user changes them. Setup remains available from the app menu and `primarypaste://show-setup`. Background launches stay quiet. Required permission problems can still bring Setup back on an active launch. Detailed settings and Support checks are secondary to getting a first paste working.

The onboarding approach follows Apple's [onboarding](https://developer.apple.com/design/human-interface-guidelines/onboarding) and [privacy](https://developer.apple.com/design/human-interface-guidelines/privacy) guidance: a brief practical introduction, explanations beside the relevant action, and permission requests tied to the enabled feature.

## Behavior that must hold

- Safe Drag captures deliberate drags and ignores automatic selections such as browser address-field focus. Enabled Custom Gestures capture only their selected gesture kinds.
- A deliberate drag retains only its settled selection, rather than filling history with intermediate strings. Gesture completion schedules a settled selection read. Editors that omit Accessibility notifications should not depend solely on the one-second fallback poll.
- Middle-click pastes only into an editable target under Standard rules. Links, tabs, and other controls retain native behavior. App-specific fallbacks are explicit and reversible.
- Queued pastes recheck the app, focused field, permission, retained item, and clipboard. Cancelled requests keep their items. Item consumption happens after insertion succeeds or a paste command is sent.
- Direct insertion or a sent paste command is evidence of delivery, not proof of the target accepting a file or attachment.
- Temporary clipboard operations have one owner. Available representations of every item are restored using fresh pasteboard objects. A newer clipboard change wins. Lazy app-specific formats remain best-effort.
- Primary and the normal clipboard stay separate by default. Import Copies and Mirror Selections must avoid feedback loops. Transient, autogenerated, and concealed copies are excluded from import.
- Pausing stops capture and paste. Private Mode stops new capture while allowing existing Primary items to paste. Blocked apps, secure fields, and sensitive-looking text remain capture boundaries.
- Text and Finder caps refuse an over-limit selection as a whole and keep the previous Primary item. Capture feedback clears when content is cleared, feedback is disabled, or Private Mode begins.
- Latest, Queue, Stack, and Cycle previews match the next item. Changing retention prunes immediately, with Cycle staying valid. Removal is optional for Queue and Stack and is disabled in Cycle.
- Diagnostics contain decisions and app identities, never selection content, clipboard contents, file paths, or license credentials.

## Automated checks

`./Scripts/check.sh` runs formatting, architecture/privacy checks, dependency auditing, backend type checks and SQLite/cryptography integration tests, the unsigned app build, hostless XCTest, and structural preflight.

`./Scripts/install_dev_app.sh` builds and signs the supported app, validates the staged installation, retains the previous copy for recovery, and registers `/Applications/Primary Paste.app` with Launch Services. Bundle ID and signing identity remain stable.

`./Scripts/phase6_verify.sh` checks the installed app's identity, executable, signature, URL scheme, Finder entitlement, and running state. `BUILT_APP_PATH` also compares the installed executable with the verified build. `STRUCTURAL_ONLY=1` omits installed-app checks. Preflight does not perform UI automation or mark App Checks complete.

The existing `phase6_smoke.sh` offers additional quiet and optional UI/launch checks. Its UI lane uses AppleScript and requires an appropriately authorized automation host. Do not treat source-string checks, shell Accessibility warnings, or a successful process launch as real gesture proof.

## Testing without interrupting daily work

The default quality gate uses hostless XCTest and backend tests. These checks can run in the background without taking over the user's desktop. Browser DOM tests can use isolated tabs, but they do not prove native global-input delivery or the macOS clipboard transport.

Native acceptance needs its own active macOS GUI session. Prefer a dedicated Mac or an Apple Silicon macOS VM. Run automation inside that guest, rather than using the host cursor to drive the VM window. Keep host/guest clipboard sharing off and use disposable samples; otherwise a clipboard test can cross the isolation boundary. Grant the test app and automation helper their required permissions inside the guest. Use a stable signed app identity and restart from a known clean test state. Parallelize independent background checks, but serialize global input and normal-clipboard operations within each GUI session.

The VM establishes target-app behavior in that environment. A final physical-host smoke check still covers the actual mouse or trackpad mapping and the installed app's grants. See [UTM's macOS guest documentation](https://docs.getutm.app/guest-support/macos/) for supported virtualization and clipboard-sharing options.

The local disposable environment, first setup, reset, and teardown commands are documented in [QA-VM](QA-VM.md). Its owned manifest and lifecycle safeguards keep the VM and its support files separate from the app installation and repository evidence.

## Real-app acceptance

Use the signed installed app and disposable local samples. Restore any temporary settings. In Support → App Checks, distinguish observed runtime evidence from manually recorded completion; keep target acceptance separate from command delivery.

| Check | Targets and expected result |
| --- | --- |
| Text capture | Browser page, native text editor, terminal selection, Codex composer, Finder rename field. A deliberate selection becomes the exact next Primary text. Record unsupported AX surfaces and any explicit fallback needed. |
| Automatic selection | Focus a browser address field without a selection gesture. The existing Primary item stays unchanged. |
| Text paste | Native field, browser input/textarea/contenteditable, Codex composer. Paste replaces the intended range or inserts at the caret; whitespace and Unicode remain exact. |
| Native middle-click | Browser link and tab, plus a non-editable native control. Native behavior still occurs; no Primary paste is sent. |
| Focus/cancellation | Change app or field during a delayed paste, pause, or clear Primary. No later paste reaches an unintended target and no unrelated clipboard change is restored over. |
| Normal clipboard | Cmd+C/Cmd+V in Separate remain ordinary clipboard actions. Check Import Copies and Mirror Selections with benign samples and no feedback loops. |
| Rich clipboard | Representative rich text, multiple items, images, and file references survive a temporary text paste. Check a real clipboard manager when one is available. |
| Finder files | Select one and several harmless files, then paste into an app that accepts attachments. Verify actual attachment acceptance, not just Finder readiness or a sent command. |
| Caps | Exceed text and Finder limits. A warning appears and the previous Primary remains available. |
| Privacy | Private Mode, a blocked app, a secure field, and a synthetic sensitive-looking string prevent capture. The built-in filter self-test supports this check but does not replace it. |
| Permissions/relaunch | Required permission loss stops the affected service; restoring access recovers it. Rebuild/relaunch preserves app identity and existing grants. Changing macOS permission grants requires user involvement when the automation policy requires it. |
| Quiet operation | Continue in Menu Bar, relaunch, and return to work. No unnecessary Setup window, focus change, clipboard change, or repeated notification. |

App compatibility is bounded by the target's Accessibility exposure and paste handling. A fallback may be necessary for terminals or editors that hide their selection/fields. Keep the default behavior conservative rather than silently issuing copy/paste commands in every app.
